Concurrency Problems

Dirty Read

Reading uncommitted data from another transaction that later rolls back.

Tx A writes X=50
Tx A Rollback!
Tx B reads X=50

Non-Repeatable Read

Reading the same row twice gets different data because another transaction modified it.

Tx A reads: 100
Tx B updates to 200 & commits
Tx A reads: 200 (Changed!)

Phantom Read

Executing the same range query twice returns a different set of rows (inserts/deletes).

Tx A: SELECT > 10 (3 rows)
Tx B: INSERT row 15 & commits
Tx A: SELECT > 10 (4 rows 👻)

Lost Update

Two transactions update the same data simultaneously, one overwrites the other.

Tx A reads 100 | Tx B reads 100
Tx A adds 50 -> writes 150
Tx B adds 100 -> writes 200
150 is lost! Final is 200.

MySQL vs PostgreSQL

🐬

MySQL

InnoDB Engine

  • 👉 Row-level locking
  • ✅ MVCC supported
  • ⚙️ Default: Repeatable Read

MyISAM Engine (Legacy)

  • ⚠️ Table-level locking only
  • ❌ No MVCC
🐘

PostgreSQL

Advanced MVCC

  • 📖 Reads NEVER block writes
  • ✍️ Writers NEVER block reads
  • ⚙️ Default: Read Committed
  • ✅ True Serializable Snapshot Isolation
